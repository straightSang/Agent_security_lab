## 배운 것
처음 세 번의 시도는 authorization 단계에서 멈춰 _write_file에 도달조차
못 했다. write_file은 승인이 필요한 도구이고, 소유권은 경로의 두 번째
조각(data/{actor}/)으로 판정된다. 따라서 이 불변조건을 검증하려면

  1. 소유자가 ACTOR인 경로를 쓰고      (data/user-001/...)
  2. 승인을 먼저 받아 approval_id를 넘겨야 한다

테스트가 통과한다고 해서 의도한 코드에 도달했다는 뜻은 아니다.
end_stage를 확인하지 않았다면 세 번 모두 "통과"로 오인했을 것이다.

## 반례 / 실패한 run

error.code와 meta.reason이 다른 값을 담는다는 것을 D9-E11에서 알았다.

    error.code   MISSING_REQUIRED_APPROVER      실패한 직접 원인
    meta.reason  WRITE_REQUIRES_EXPLICIT_APPROVAL  정책이 판단한 사유

meta는 관문들이 거쳐 간 누적 기록이고 error가 최종 원인이다. 둘을 혼동하면
"왜 실패했나"를 잘못 인용하게 된다. 보고서에 인용할 값은 error.code다.
